## Purpose
The routing plane joins catalog facts, operator policy, request demand, live quota, failure backoff, effective cost, and observed speed to select a reproducible provider/model route. It records every decision so later explanation can show the selected route, rejected candidates, provenance, objective, and outcome. (`crates/prefrontal-routing-core/src/model_router.rs:409-538`, `crates/prefrontal-routing-core/src/model_router.rs:557-631`, `crates/prefrontal-routing-module/src/main.rs:1918-1920`)

## Vocabulary
Route key: the canonical provider and model identity; Fusiform and the store key facts by provider plus model and never by a bare model id. (`crates/prefrontal-routing-store/tests/it/route_state_store.rs:2344-2383`)

Catalog fact: existence, token limits, capabilities, and output price synchronized from Fusiform, subject to a same-field operator override. (`crates/prefrontal-routing-module/src/fusiform_catalog.rs:3-12`, `crates/prefrontal-routing-core/src/route_state_store.rs:32-39`)

Score provenance: `Curated`, `Override`, `AaInferred`, or `Unscored`; unscored facts are known but not routable. (`crates/prefrontal-routing-core/src/model_facts.rs:178-204`)

Demand: IQ and EQ numbers must be within 0 through 100; the demand-bar calculation clamps its input to that same scale. (`crates/prefrontal-routing-core/src/routing_config.rs:48-62`, `crates/prefrontal-routing-core/src/model_router.rs:655-667`)

Demand bar: `top_score * (demand / 100)^0.35`; a model's fit on each demanded axis is capped at 1.0. (`crates/prefrontal-routing-core/src/routing_config.rs:13-13`, `crates/prefrontal-routing-core/src/routing_config.rs:48-62`)

Adequacy: the demand-weighted Elo and EQ fit after confidence penalty. Normal routing requires 0.90; best effort may run from 0.60 to 0.90 and emits `belowFloor`. (`crates/prefrontal-routing-core/src/route_scoring.rs:58-117`, `crates/prefrontal-routing-core/src/routing_config.rs:71-79`, `crates/prefrontal-routing-core/src/model_router.rs:727-776`)

Static admission: catalog, exclusion, availability, capability, context, and fast-variant gates applied before transient quota and cooldown state. (`crates/prefrontal-routing-core/src/model_router.rs:409-538`)

Operator exclusion: `model_routing.exclude` (groups `all`, `mason`, `sidekick`, `athena`, `lab`, `core`, with `-` exceptions inside a group) keeps a route out of automatic choice only: unpinned `route.select`, class-policy panel seats and extra draws, fallback, failover, and reroute. A request that names its model (`work(model=...)`, a synthesizer or lab-planner pin, an admission pin) is admitted even when the route or its provider is excluded, as long as it is otherwise servable: credentials, availability, capability, context window, and quota walls still refuse it. There is no separate explicit-only list; `model_routing.explicit_only_providers` is refused at load with `config_key_removed` and the remedy "list the provider in model_routing.exclude.all; an explicit model pin is still admitted". (`crates/prefrontal-routing-module/src/work_model_pin.rs`, `crates/prefrontal-routing-module/src/select_policy.rs`, `crates/prefrontal-routing-module/src/config_overrides.rs`)

Variant overrides: `model_routing.variants` uses the same groups as `exclude` (`all`, `mason`, `sidekick`, `athena`, `lab`, `core`). Each group maps a route spec in the exclusion grammar (`provider`, `provider/model`, `provider/model/variant`; no `-` entries) to a reasoning variant, and within a group the most specific matching key wins. A selection runs at the first of: (1) a variant the caller names (`provider/model:variant`, an admission pin's or synthesizer pin's `variant`); (2) `variants.<consumer>`; (3) `variants.all`; (4) the curated default on the route's fact row. Panels apply it per seat, extra draws included: lab panels read `variants.lab`, every other class `variants.athena`. The authority for which variants exist is the catalog: Fusiform's `capability.reasoning_options`, whose `effort` values routing stores per model (`model_facts.reasoning_efforts_json`, migration 50). Startup (once the store opens) and every reload refuse an override whose variant a matched model does not publish, whose model publishes no effort values, or whose key matches no catalog model, naming the route, the variant and the published list; a refused reload keeps the last good config. `--check-config` runs the same check against the store at `$XDG_DATA_HOME/cortexkit/prefrontal-routing/store.db` (default `~/.local/share/...`) opened read-only, or prints why it skipped. A model not yet read from the catalog since migration 50 is a warning, not a refusal. If the catalog later stops publishing a configured variant, selection does not fail: it uses the next rule and records the skip in `variantSelection.fallbacks` on the `route.select` reply and as `variant fallback:` lines in the decision explanation. `route.select` replies carry `variantSelection` (`variant`, `source` = `pin`, `consumer`, `all` or `curated`); panel policies carry `reasoningVariant`, `reasoningVariantSource` and `reasoningVariantFallbacks` on each `seatedVariants` entry. (`crates/prefrontal-routing-module/src/variant_policy.rs`, `crates/prefrontal-routing-module/src/config_overrides.rs`, `crates/prefrontal-routing-store/src/reasoning_catalog.rs`, `crates/prefrontal-routing-module/src/fusiform_catalog.rs`)

Pinned variants: a `modelPin` naming `provider/model:variant` is checked against the same published efforts, following a `score_alias` provider to the provider whose catalog rows it borrows. A variant outside a published list is refused with `invalid_model_variant`, naming the list. A model the catalog has not been read for yet (or a module whose store has not opened) admits the pin, leaves the decision to Broca, and adds a `not checked` line to the decision explanation. Core runs each Athena seat (round zero, spec campaigns and replacement seats) at `seatedVariants[slot].reasoningVariant` when routing sends it, and at the member's `promptParams.variant` otherwise. It records the result as `seatVariant {variant, source}` on the member in the consult's stored panel; the source is routing's `reasoningVariantSource`, or `prompt_params` when routing sent no per-seat variant. (`crates/prefrontal-routing-module/src/work_model_pin.rs`, `crates/prefrontal-core-module/src/routing_cooldown.rs`)

Effective price: output list price divided by a positive finite subscription multiplier; unknown price normalizes to maximum cost rather than zero. (`crates/prefrontal-routing-core/src/model_router.rs:311-340`)

Selection cost: normalized effective price plus quota pressure weighted by 0.5. (`crates/prefrontal-routing-core/src/model_router.rs:557-631`, `crates/prefrontal-routing-core/src/routing_config.rs:84-86`)

Effectively-free bucket: routes at or below selection cost 0.05 compare adequacy before speed and ignore smaller cost differences. (`crates/prefrontal-routing-core/src/routing_config.rs:82-82`, `crates/prefrontal-routing-core/src/model_router.rs:831-848`)

Quota wall: a route or account exclusion caused by explicit exhaustion, utilization at or above 0.99, or a reported spendable non-positive pool. (`crates/prefrontal-routing-core/src/quota.rs:249-306`, `crates/prefrontal-routing-core/src/quota.rs:114-125`)

Failure backoff: route-local cooldown whose default threshold is three consecutive route-attributable terminal failures; it begins at ten minutes and doubles to a six-hour cap. (`crates/prefrontal-routing-core/src/failure_backoff.rs:8-23`, `crates/prefrontal-routing-core/src/failure_backoff.rs:132-182`)

Routing decision: the durable selected route, request, candidate explanations, policy provenance, and later outcome addressed by decision id or send id. (`crates/prefrontal-routing-store/src/lib.rs:485-537`, `crates/prefrontal-routing-module/src/main.rs:3166-3282`)

## Surfaces
- Tools (agent-facing): routing is automatic for supported worker launches; the TypeScript consumer forwards model-fact, selection, policy, outcome, usage, cooldown, and backoff calls to the routing module. (`packages/core/src/features/model-routing/routing-consumer.ts:110-242`, `packages/core/src/features/model-routing/agent-route-defaults.ts:1-7`)
- Wire operations (subc): Mutate operations are `route.select`, `route.model_upsert`, `route.model_seed_aa`, `route.select_panel`, `route.set_decision_outcome`, `route.record_usage`, `route.record_cooldown`, `route.clear_failure_backoff`, and `route.clear_cooldown`. Query operations are `route.resolve_policy`, `route.model_fact`, `route.model_facts`, `route.list_inferred`, `route.list_unscored`, `route.list_canonical_gaps`, `route.cooldown_status`, `route.explain`, `route.decisions_list`, and `route.quota_status`. (`crates/prefrontal-routing-module/src/main.rs:3687-3784`)
- Self-diagnosis: the query operation `diagnostics.findings` (request `{window_ms?}`, default six hours) reports `credential_fences`, `route_blocks`, `refusal_rate` and `empty_candidate_sets` findings as `{generated_at_ms, window_ms, findings: [{check, key, severity, count, first_seen_ms, last_seen_ms, summary, samples, hint}]}`, under 64 KiB and empty when routing is healthy. Slot saturation is not checked because routing stores no slot counts. Only head routes and flow scopes may call it. Routing provides `flow-scopes/v1` for this op alone: on a route whose scope carries a `flow_id`, every other op is refused with `flow_scope_not_supported`. (`crates/prefrontal-routing-module/src/diagnostics_findings.rs`)
- `route.select` accepts requirements, available models, exclusions, capabilities, subscription, routing policy, and launch correlation; it returns a selected route with objective and decision id or a typed failure. (`packages/core/src/features/model-routing/routing-consumer.ts:49-73`, `packages/core/src/features/model-routing/routing-consumer.ts:141-162`)
- `route.resolve_policy` merges curated, operator, and caller subscription facts and exclusions before selection. (`crates/prefrontal-routing-core/src/launch_policy.rs:140-196`, `packages/core/src/features/model-routing/subscription-classifier.ts:15-45`)
- `route.set_decision_outcome` records a terminal or non-terminal outcome and advances failure-backoff state; `route.clear_failure_backoff` explicitly removes only route-local terminal-failure backoff. (`crates/prefrontal-routing-module/src/main.rs:2924-2992`, `crates/prefrontal-routing-module/src/main.rs:3751-3762`)
- `route.record_usage` persists token and duration observations used to replace catalog speed after enough recent samples. (`crates/prefrontal-routing-store/src/lib.rs:2008-2020`, `crates/prefrontal-routing-store/src/lib.rs:2099-2136`)
- `route.explain` requires exactly one `decisionID` or `sendID` and returns the recorded decision, rejections, quota snapshot, catalog and policy identities, provenance, and outcome without rescoring. (`crates/prefrontal-routing-module/src/main.rs:3193-3282`)
- `route.decisions_list` filters retained decisions by send id, target agent, route key, and inclusive time bounds with a limit from 1 through 100. (`crates/prefrontal-routing-module/src/main.rs:3324-3387`)
- Fusiform surface: the consumer calls `catalog.get` and `catalog.status` on module `fusiform`; a durable cursor stores catalog version and resolve time. (`crates/prefrontal-routing-module/src/fusiform_catalog.rs:33-35`, `crates/prefrontal-routing-store/src/lib.rs:388-392`)
- Shared model scores: Fusiform's `model.canonical_id` is stored per route; a route without an operator Elo/EQ reads the operator score of a route with the same canonical id and variant, its own score winning on disagreement; a null id never borrows. `route.model_upsert` with `canonicalID` places Elo/EQ on every stored route of that model; `route.list_canonical_gaps` lists scored routes whose row states no canonical id. (`crates/prefrontal-routing-core/src/canonical_scores.rs`, `crates/prefrontal-routing-store/src/lib.rs`, `crates/prefrontal-routing-module/src/main.rs`)
- Upstream status: Fusiform's `model.status` is stored per route; a route marked `deprecated` (models.dev's mark for a model OpenCode withdrew) is refused with `deprecated_upstream` for automatic selection, panel seats and extra draws, and for explicit pins; `beta` and `alpha` are routable. (`crates/prefrontal-routing-core/src/model_router.rs`, `crates/prefrontal-routing-module/src/work_model_pin.rs`)
- Credential refusal fences: `route.set_decision_outcome`'s optional `providerOutcome.credentialRefusal` (`providerId`, `credentialId`, `code`) reports a provider's permanent refusal of one vault credential: `ENTITLEMENT_ERROR`, an empty balance (`billing_exhausted`), or a balance too small for the request (`credit_insufficient`, fenced as `credential_billing_exhausted`). Routing stores the (provider, credential) pair in `credential_entitlement_fences` until that credential's vault listing (provider ids, plan tier, state) changes; there is no expiry. Automatic selection and panel seats reject a route whose every serving credential is fenced with `credential_unentitled` or `credential_billing_exhausted` and `credentialIds`; a route another credential serves stays eligible and its Broca launch is pinned to that credential; an API-key pool (`route.pool_acquire`) never leases a fenced key and keeps leasing its other keys. Explicit model pins are not fenced, but the key a pool picks for one still skips fenced keys. Core reports only a credential Broca names: `run.status.auth_selection` (Broca 0.3.251+), else the run error's `credential_id`. Unknown report fields are ignored. (`crates/prefrontal-routing-module/src/credential_fences.rs`, `crates/prefrontal-routing-module/src/key_pool.rs`, `crates/prefrontal-core-module/src/llm_runner_consumer/credential_refusal.rs`)
- AA surface: `route.model_seed_aa` ingests a mapped Artificial Analysis index; `route.list_inferred` and `route.list_unscored` expose inferred and awaiting-placement rows. (`crates/prefrontal-routing-module/src/main.rs:106-110`, `crates/prefrontal-routing-module/src/aa_ingest.rs:27-110`)
- Configuration: model facts, operator exclusions, and subscriptions come from `~/.config/cortexkit/prefrontal-routing.jsonc`; malformed operator edits retain the last valid cached policy. (`crates/prefrontal-routing-module/src/config_overrides.rs:1-12`, `crates/prefrontal-routing-module/src/config_overrides.rs:29-33`, `crates/prefrontal-routing-module/src/config_overrides.rs:756-821`)
- Configuration: provider/model specs accept provider or provider/model inclusion and the same forms prefixed by `-` for exclusion. Operator and caller exclusions are checked independently, so caller negation cannot reopen an operator fence. (`crates/prefrontal-routing-core/src/provider_model_spec.rs:17-100`, `crates/prefrontal-routing-core/src/provider_model_spec.rs:137-176`, `crates/prefrontal-routing-core/src/provider_model_spec.rs:252-289`)
- Configuration: `subscription_multiplier` must be finite and greater than zero; AA uses a vault `api_key_ref`, explicit route-key map, and default 14-day review period, while inline API keys are refused. (`crates/prefrontal-routing-module/src/config_overrides.rs:108-183`, `crates/prefrontal-routing-module/src/config_overrides.rs:1234-1360`)
- Panel routing: `route.select_panel` seats panels from the operator's class policy (`model_routing.panels`); caller rosters are refused. Every seat, including extra draws, is an automatic choice, so `exclude.all` and the class's `athena` or `lab` group never seat an excluded route; availability, quota, cooldown, and capability gates also apply, and seating may enforce labeled-family diversity, temperature spread, and typed shortfall. (`crates/prefrontal-routing-core/src/panel.rs`, `crates/prefrontal-routing-module/src/panel_policy.rs`)
- Seat routing: an exact provider/model pin has precedence and fails if unavailable or below the 0.90 floor; otherwise ordered model, provider, and family recommendations are considered with known-family diversity. (`crates/prefrontal-routing-core/src/seat_routing.rs:222-327`, `crates/prefrontal-routing-core/src/seat_routing.rs:329-435`)

## State
- The route state store applies 34 SQLite migrations for model facts and overrides, catalog and AA state, quota and failure state, usage observations, decisions, rejections, and outcomes. (`crates/prefrontal-routing-store/src/lib.rs:143-282`)
- Model facts distinguish seed, override, AA-inferred, and unscored sources; seed and override rows block AA inference from replacing their scores. (`crates/prefrontal-routing-core/src/route_state_store.rs:22-74`)

- Observed speed uses at least 50 output tokens, five samples, up to twenty samples, and a trailing seven-day window; its query uses `model_route_usage_route_observed_idx`. (`crates/prefrontal-routing-core/src/route_state_store.rs:89-92`, `crates/prefrontal-routing-store/src/lib.rs:22-24`, `crates/prefrontal-routing-store/src/lib.rs:125-134`)
- Quota cache entries are isolated by provider and account; one exhausted account does not wall a provider while a sibling account remains usable. (`crates/prefrontal-routing-core/src/quota.rs:366-373`, `crates/prefrontal-routing-core/tests/it/quota_overlay.rs:450-505`)
- Routing decisions are retained for `retention.model_route_decisions_days` (default 30) and expired rows are pruned by the module's retention pass through `delete_decisions_older_than`, at most 256 rows per call. The same 60-second pass bounds served account-selection history (`retention.account_selection_days`, default 30, after each row's last activity and only once nothing references it), purges the retired shadow `account_decision` rows whatever their age, and bounds `account_observation` (7 days) and `model_route_usage` (30 days, never below the 7-day speed window). (`crates/prefrontal-routing-module/src/retention.rs` (`run_retention_pass`), `crates/prefrontal-routing-store/src/retention.rs`, `crates/prefrontal-routing-store/src/lib.rs:2929-2945`)

## Lifecycle
1. Fusiform synchronization decodes served catalog rates as priced, stated-zero, unpriced, or refused; non-USD, negative, and excessive-exponent prices become unknown maximum cost rather than crashing selection. (`crates/prefrontal-routing-module/src/fusiform_catalog.rs:126-219`)
2. First-sight models under operator-known providers enter the store as unscored and cannot route until an operator override, curated seed, or AA inference supplies score placement. (`crates/prefrontal-routing-store/src/lib.rs:830-845`, `crates/prefrontal-routing-core/src/model_facts.rs:202-204`)
3. AA maps an exact route key to an index, interpolates the embedded Elo curve, applies a 30 percent floor-gap penalty, inherits EQ from the closest curated neighbor, and uses default speed 100. (`crates/prefrontal-routing-core/src/aa_infer.rs:21-54`, `crates/prefrontal-routing-core/src/aa_infer.rs:103-169`)
4. Policy resolution combines curated and authenticated subscription providers, operator rules, and caller rules. Operator factual overrides remain authoritative, and operator exclusions are authoritative for automatic choice; a request that names its model keeps excluded routes in its available set. (`crates/prefrontal-routing-core/src/launch_policy.rs:140-196`, `crates/prefrontal-routing-core/src/provider_model_spec.rs:137-176`)
5. Selection validates IQ and EQ, rejects statically inadmissible routes, overlays cooldown, quota, and failure backoff, and computes the top routable quality frontier without transient walls. (`crates/prefrontal-routing-core/src/model_router.rs:409-538`, `crates/prefrontal-routing-core/src/model_router.rs:655-683`)
6. The scorer refuses below 0.60, uses best effort from 0.60 through 0.90, and normally shortlists only routes at or above 0.90. Cheapness and speed cannot pull a sub-bar model into the shortlist. (`crates/prefrontal-routing-core/src/model_router.rs:727-776`, `crates/prefrontal-routing-core/tests/model_router.rs:207-210`)
7. Within the shortlist, the scorer compares prompt-cache preference and selection cost; two effectively-free routes compare adequacy, then normalized speed from 50 to 200 tokens per second. (`crates/prefrontal-routing-core/src/model_router.rs:831-848`, `crates/prefrontal-routing-core/src/model_router.rs:541-543`)
8. Quota merging walls a route at explicit exhaustion or 99 percent use. Missing reset time uses a six-hour reprobe horizon; if every candidate is exhausted, break-glass probes the earliest reset across route and capacity scopes. (`crates/prefrontal-routing-core/src/quota.rs:249-306`, `crates/prefrontal-routing-core/src/break_glass.rs:72-130`)
9. Panel selection shares route admission, collapses requested family diversity, and reports shortfall rather than fabricating unlabeled diversity. Seat selection evaluates a model pin first and then recommendation tiers. (`crates/prefrontal-routing-core/src/panel.rs:289-315`, `crates/prefrontal-routing-core/src/panel.rs:392-505`, `crates/prefrontal-routing-core/src/seat_routing.rs:250-327`, `crates/prefrontal-routing-core/src/seat_routing.rs:329-435`)
10. The module records the chosen decision and every rejected candidate before returning; later outcome reports update the record and failure streak. (`crates/prefrontal-routing-module/src/main.rs:2684-2772`, `crates/prefrontal-routing-store/src/lib.rs:1704-1749`, `crates/prefrontal-routing-module/src/main.rs:2924-2992`)
11. Usage reports add observed speed samples. Five qualifying recent samples replace the static speed input on later selections. (`crates/prefrontal-routing-store/src/lib.rs:2008-2020`, `crates/prefrontal-routing-store/src/lib.rs:2099-2136`)
12. On restart, the store migrations and open path restore durable facts, cursors, backoff, usage, and decisions; background Fusiform, AA, and quota consumers refresh external state. (`crates/prefrontal-routing-store/src/lib.rs:143-282`, `crates/prefrontal-routing-store/src/lib.rs:558-579`, `crates/prefrontal-routing-module/src/main.rs:113-123`)

## Subscription economics (2026-10-09)

Live subscription selections price consumed quota rather than a hand-set subsidy proxy. A pooled point is one percent of one account's weekly window. The existing basket supplies **unclamped list USD per message**; message points are `list USD / value USD per point`. Comparable subscription dollars are `message points × (monthly plan fee / 100) × plan pressure`, normalized by the existing basket reference. Output-only fallback retains its common million-output-token reference unit; it does not invent a token basket. Metered pricing, adequacy gates, prompt-cache preference, overqualification and its fit guard remain unchanged. Quota-priced candidates keep their own basket cost even within one provider; relative 10% economic bands give prices in the same band one cost key so adequacy can break the tie, without inconsistent pairwise tolerance rankings. (`crates/prefrontal-routing-core/src/model_router.rs`, `compute_objective`, `route_order_keys`)

Value precedence is **operator → Astrocyte → Fusiform → conservative default**. Existing `model_routing.subscription_multipliers` (including route-specific overrides) remain multipliers in list USD per subscription USD, converted with the plan's fee per point; no operator config is removed. Astrocyte's `spend.multiplier.report` supplies API list-price nanos (`api_nanos`) and pooled percentage-point consumption (`delta_percent`); `api_nanos / 1e9 / delta_percent` is list USD per quota point. A positive row is accepted only while its **interval end** is under 48 hours old; recomputing an old day does not refresh its evidence. The explanation names the row date. Fusiform's optional `plan.prices.quota_value` is read only with an operator `plan_tier` carried through `credential.list_scoped` into the roster. Measured ranges use `low`; absent, `not_established`, malformed, future-dated or past-review values fall through. Unknown defaults to a conservative **1×** multiplier and is labeled **unmeasured**, never a fabricated measurement. Fees come from tier-matched Fusiform prices or Astrocyte's per-account plan prices; when neither is known, $200 is the explicit conservative fee assumption. (`crates/prefrontal-routing-core/src/subscription.rs`, `resolve_value`; `crates/prefrontal-routing-module/src/subscription_economics.rs`)

Subscription pricing multiplies the plan fee per consumed point by a quota-scarcity factor called pressure. Its formula is parameter-free: `remaining window fraction / remaining headroom share²`, bounded to `[0.01, 1,000,000]`. It rises monotonically as headroom shrinks, steeply near a wall, and makes expiring unused headroom cheap. Weekly headroom is pooled across unwalled accounts, using `rawUsedPercent` when present; zeroed effective use from saved resets is not free live quota. Paid capacity remains 100 points per known account even when an account walls, so hitting a wall cannot reduce pressure by shrinking its denominator. The largest remaining weekly fraction in a pool governs time pressure; reported shorter windows are pooled by duration and the strongest window pressure governs. (`crates/prefrontal-routing-core/src/subscription.rs`, `SubscriptionPlan::budget`)

`model_routing.keep_free_percent` is a provider-keyed map beside `subscription_multipliers`, validated in `0..100`, default 0. It is the only head-protection reservation: workers may spend the sum of `max(100 − raw use − margin, 0)` over live accounts whose weekly usage is below 100 and which have no short-window wall. Head callers named `alfonso`, `head`, `opencode`, `pi`, or `claude-code` ignore the margin, but not quota walls. Unknown caller classes are workers. If no eligible account has quota above its per-account keep-free margin, the route rejects workers as `subscription_reserve` (subject to the unchanged emergency banked-reset allowance below). Missing readings fail closed for workers with a nonzero margin. Setting the margin to zero removes head protection; neither recent head activity nor projected future demand can withhold live worker quota. Routing does not request `spend.multiplier.pace` or emit head-pace/reset-projection diagnostics. Astrocyte's `spend.multiplier.report` still supplies quota value for pricing; its fixture was captured from the real read-only operation and pins its source commit. (`crates/prefrontal-routing-core/src/subscription.rs`, `SubscriptionPlan::budget`; `crates/prefrontal-routing-module/src/subscription_economics.rs`, `refresh`)

Banked resets are outside live headroom. At no more than 10% live headroom, an account at at least 90% raw weekly use may lower pressure with one unexpired saved reset, earliest expiry first. Free unreserved live headroom on a different tier or provider plan disables that emergency credit. A banked reset contributes 100 points minus the provider's configured `keep_free_percent` for workers; it cannot reopen a 100% worker margin. Insula's `soonestExpiresAt` and `credits[].expiresAt` determine expiry. (`crates/prefrontal-routing-core/src/subscription.rs`, `SubscriptionPlan::budget`; `crates/prefrontal-routing-module/src/subscription_economics.rs`, `set_banked_allowance`)

The existing account-quota slow loop refreshes subscription value per point, plan prices, and pooled account headroom off the selection path (normally every 60 seconds). No selection performs a subc call. Account readings and roster metadata survive in routing's store; derived economics stay in memory, and readings older than 15 minutes lose authority. Missing Astrocyte/Fusiform modules and optional operations are normal, not routing errors. Decisions persist the pricing breakdown and explanation (value/source, pooled message points, fee per point, pressure, fixed keep-free margin, banked use); route-dry-run already prints these explanation lines. Account-quota health lists each unknown/refused/overdue credential tier once as `unpriced plan tier: <provider>/<tier>`. (`crates/prefrontal-routing-module/src/account_quota.rs`, `account_quota_loop`, `status_json`; `crates/prefrontal-routing-module/src/subscription_economics.rs`, `health_detail`)

**Boundary:** the keep-free margin is enforced where the pooled plan budget is chosen, not inside `account_for`. The `account_for` allocator still chooses which account serves each model request and has no caller-class signal. Per-account fencing would require propagating that class into `account_for`; its runner field (Broca versus host plugin) is currently the closest proxy because heads do not run on Broca yet. Margin-based pricing therefore leaves the `account_for` API unchanged.

The scenario test with required IQ 70 (the caller's capability threshold on a 0–100 scale) uses Claude raw use 3%, 3%, 51%, 53% and one walled account, Codex Pro raw use 73% and 89% with saved resets, and a walled Pro Lite (`pro_100`, $100) plan. Both active plans cost $200. With 20% of each Claude weekly account window reserved from workers, Claude wins using $28.40/point versus Codex $9.42/point; raising Claude toward its reserved share flips the winner to Sol. Tests also pin source precedence, raw/effective use, margin/head distinction, zero-margin and nonzero-margin worker admission, pressure shape, expiring headroom, banked gating and unpriced-tier diagnostics. (`crates/prefrontal-routing-core/tests/model_router.rs`; adapter and core subscription unit tests)
